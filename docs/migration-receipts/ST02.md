## Resulting behavior and contract ownership

- New typed ctl and agent MCP status/history/steering operations share the application service.
  It verifies managed/external provenance before target disclosure, matches the original external
  process generation, and positively verifies native human eligibility. Owner labels/connection
  names and opaque IDs never grant authority. Native take/release ownership uses epoch CAS;
  same-process reconnect is supported, external process-restart enrollment remains unsupported.
- Root builder requests carry exact target/draft/source/control identities and idempotent request
  digests. Qualified durable ledger/schema and bounded history preserve requests, issuance,
  claims, usage provenance and replies across restart. Unknown delivery never grants another spawn.
- Each explicit request authorizes one issuance. Prose persists and waits; strict whole-final
  command framing plus role/source/draft/witness validation creates only an unsaved proposal.
  No automatic repair, feedback continuation, provider fallback or caller/model conversation loop.
- Active-turn steering queues without interruption. The shared root lock chooses admission versus
  old finalization/autosave. Old final/output and already-published previews remain real evidence;
  superseded finalization cannot publish/save. Changed preview/source/issued identity becomes stale.
  Restart observes the same old boundary task before one requested continuation; unknown capture
  retains the hold. A valid final proposal completes the builder without saving a definition.
- Existing ordinary create autosave and preview-summary completion remain intact. The builder keeps
  configured read-only authority, active preview CAS and explicit editor Apply/Save. Own preview
  writes advance a turn-bound commit witness; external changes never borrow that privilege.
- Finite supported harness caps are required. Conversation issuance is permanently charged and
  separate from execution attempts; provider costs/usage retain observed/unavailable provenance.
  Read-only is a harness permission mode, not a new OS confinement or dollar/tool-effect guarantee.

Producer owns canonical contracts until accepted O04 transfer. New capabilities are
`workflow-steering-read.v1` and `workflow-steering-builder.v1`; no worker/orchestrator/replan or
new normalized-task-event capability is advertised. Existing ctl/event v1 envelopes remain.
Public [contracts](../contracts.md#builder-conversation-steering) and
[workflow guide](../workflows.md#explicit-builder-conversation-steering) describe actual scope.
