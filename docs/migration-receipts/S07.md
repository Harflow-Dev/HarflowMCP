## Delivered infrastructure and boundaries

`conformance/` supplies a standard-library runner with independent contract,
capture and process observations. The source profile archives an exact committed
repository into the new output directory, validates safe archive entries, and
loads the public CLI from that snapshot under isolated Python. An explicit
binary profile accepts `--engine-bin`/`HARFLOW_ENGINE_BIN` only with a caller-pinned
SHA-256; binary and source selection cannot be combined. Binary adapter self-checks
use stubs and do not qualify Rust.

Engine commands are restricted to `version-info --json` and `state-inspect --json`
against a fresh missing root. Each ordinary command receives its own fresh
handshake, followed by independent response checks. No task launch is permitted.
The standalone deterministic fake exercises process/capture infrastructure in
version, success, nonzero, hang, flood and pipe-holder modes. Its own observation
is untrusted; parent-owned PID/argv/nonce, captures and exit evidence corroborate it.
It is not routed through the engine and is not yet a backend-compatible harness.

The independently pinned manifest is
`383ecf7a9b234a1ece18eb15585398f08a77205c02a43cb2a928a2819f76fee0` with 199 fixtures.
Every fixture hash is checked; substituting a self-consistent new manifest does
not pass. MCP schemas stay separate from ctl envelopes. Independent oracles reject
wrong product/format, boolean versions, malformed JSON, wrong roots and missing
required capabilities; optional fields/kinds remain additive and nested event
writer versions remain provenance. No engine implementation helper is imported
as an outcome oracle.

The runner constructs fresh HOME/XDG/workspace/state paths and a scrubbed child
environment. Capture limits apply during dual-stream draining; deadlines and
teardown are bounded. Group signals finish while the leader remains unreaped;
there is no blind retry against a saved PGID after reaping. Failed/uncertain
cleanup retains artifacts and cannot pass. This is not an OS sandbox or proof of
containment for descendants escaping the original process group.

Caller-supplied invocation IDs, context, target/framework fingerprints, parent
spawn/exit records and capture hashes bind report evidence. Publication cannot
replace existing files. Unknown outcomes do not trigger replay. These consistency
checks are not same-user tamper-proof attestations, publisher authenticity or
complete OS/system-library qualification. Read-only checks observe final root
absence; they do not trace every transient filesystem operation.
